# File Uploads

**Framework:** CEF · **Specification:** AS-016 (Security & Compliance Engine) · **Version:** 2.0.0 · **Module:** M-SEC

**Purpose:** Define safe handling of user-supplied files. An upload endpoint invites an attacker to place arbitrary bytes, under a name they choose, onto your infrastructure.

**Language:** MUST / MUST NOT / SHOULD / MAY per RFC 2119.

**Canonical values:** `security.policy.yaml` (`file_uploads`).

---

## Admission

- **FU-01 — Authenticated and authorized.** Upload endpoints MUST require authentication and MUST authorize the specific action. An anonymous upload endpoint MUST NOT exist without a recorded decision and compensating controls.
- **FU-02 — Rate limited and quota bounded.** Uploads MUST be rate-limited per identity and bounded by quota.
- **FU-03 — Size bounded.** A maximum size MUST be enforced at the proxy *and* at the application. Unbounded uploads exhaust disk and memory.

## Type Verification

- **FU-04 — Verify by content, never by claim.** The file type MUST be determined by inspecting content. The client-supplied `Content-Type` and the file extension MUST NOT be trusted — both are attacker-controlled.
- **FU-05 — Extension allowlist.** Permitted extensions MUST be an explicit allowlist. A blocklist MUST NOT be used: it is defeated by case, by unknown extensions, and by double extensions.
- **FU-06 — Content must match the extension.** A file whose detected content disagrees with its extension MUST be rejected.
- **FU-07 — Polyglots are rejected.** A file valid as two types (an image that is also a script) MUST be rejected. Re-encoding images defeats most polyglots.

## Storage

- **FU-08 — Outside the webroot.** Uploads MUST be stored outside the document root or in object storage. A file inside the webroot may be requested directly, and if the server can execute it, the upload is remote code execution.
- **FU-09 — Never executable.** Stored files MUST NOT carry execute permissions and MUST NOT reside in a path the server will interpret.
- **FU-10 — Rename on storage.** The stored filename MUST be generated by the system (random identifier). The user's filename MUST NOT determine the storage path — it carries traversal sequences, null bytes, and reserved names.
- **FU-11 — Path is resolved against a fixed base.** The final path MUST be resolved and confirmed to remain within the intended directory (`IV-22`).
- **FU-12 — Original name is data.** The user's filename MAY be retained as metadata for display and MUST be encoded on output (`OE-01`).

## Serving

- **FU-13 — Distinct origin.** User content SHOULD be served from a separate origin or domain so that a stored payload cannot execute against the application's origin and cookies.
- **FU-14 — Force the content type.** Responses MUST set a correct `Content-Type` and `X-Content-Type-Options: nosniff` (`headers.policy`).
- **FU-15 — Download, not render.** Untrusted documents SHOULD be served with `Content-Disposition: attachment` rather than rendered inline.
- **FU-16 — Authorize every retrieval.** Access to an uploaded file MUST be authorized per request. An unguessable URL MUST NOT be treated as access control (`AZ-15`).
- **FU-17 — SVG is active content.** SVG MUST be treated as executable: sanitized, served as an attachment, or served from a distinct origin. It carries scripts.

## Processing

- **FU-18 — Scan where user-facing.** Files that other users can retrieve MUST be scanned for malware.
- **FU-19 — Strip metadata.** Image metadata (EXIF, including GPS coordinates) MUST be stripped unless retention is a recorded requirement (`privacy.policy.collection`).
- **FU-20 — Process out-of-band and sandboxed.** Parsing, resizing, and conversion MUST run outside the request path and SHOULD be sandboxed with bounded CPU, memory, and time. Media parsers are a common source of memory-safety defects.
- **FU-21 — Archives are bounded.** Archive extraction MUST bound entry count, total uncompressed size, and path targets, defending against compression bombs and traversal via archive entries.
- **FU-22 — No parsing of unneeded formats.** A format the product does not require MUST NOT be accepted (SP-09).

## Verification

The security gate verifies content-based type detection, allowlisting, storage outside the webroot, generated filenames, per-request authorization, and bounded processing.
