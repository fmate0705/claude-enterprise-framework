# Case Studies

**Framework:** CEF · **Specification:** AS-011 (Content Intelligence Engine) · **Version:** 0.1.0

**Purpose:** Fix how case studies are written. A case study MUST prove a real outcome for a real client. Fabrication is prohibited.

**Language:** MUST / MUST NOT / SHOULD / MAY per RFC 2119.

---

## Case Study Rules

- **CSD-01 — Real and permitted.** A case study MUST describe a real client and MUST be published with permission; fabricated or unauthorized cases MUST NOT be published (`CNP-22`, Article IV).
- **CSD-02 — Structure.** A case study MUST follow: context (client + situation) → problem → solution → results → proof/quote → CTA (`page-structure.md` PST-14).
- **CSD-03 — Real numbers.** Results MUST use real, verifiable metrics; invented or rounded-up figures MUST NOT be used.
- **CSD-04 — Specific problem.** The problem MUST be stated specifically in the client's terms; a generic problem statement MUST NOT be used.
- **CSD-05 — Attributed quote.** A client quote SHOULD be included, attributed to a real named person and role, used with permission.
- **CSD-06 — Honest framing.** The narrative MUST be honest about scope and contribution; overstated claims MUST NOT be used.
- **CSD-07 — Outcome-focused.** The case study MUST emphasize the client's outcome, not a feature tour (`CNP-06`).
- **CSD-08 — Confidentiality.** Sensitive details MUST be anonymized or omitted per the client's terms; confidential data MUST NOT be exposed.
- **CSD-09 — Proof links.** Where possible, results SHOULD link to verifiable proof; unverifiable claims SHOULD be qualified.
- **CSD-10 — Maintained.** Case studies MUST be kept accurate; outdated results MUST NOT be presented as current.

## Case Study Guarantees

- **CSD-G1** — Real, permitted client stories with real metrics.
- **CSD-G2** — Context → problem → solution → results structure.
- **CSD-G3** — Honest, outcome-focused, confidentiality-respecting.
