# Discovery Workflow

**Purpose:** Define the first phase of every CEF engagement — understanding the problem, the audience, the brand, and the constraints before a single line of code is written.

**Description:** Discovery is where CEF earns its quality. This workflow will govern how Claude interrogates a project brief: clarifying goals and success metrics, identifying the audience and their intent, capturing brand and voice, surfacing technical and legal constraints, and recording all of it in memory. It ends when there is enough shared understanding to plan with confidence. Skipping discovery is how generic, off-target work happens — so CEF makes it a required, structured step.

## Inputs

- The user's brief, goals, and any existing brand or product context.
- Relevant memory (`client`, `branding`, `project`) if the project is ongoing.

## Steps (to be authored)

1. Clarify the goal, audience, and definition of success.
2. Capture brand, voice, and visual direction.
3. Surface technical, performance, accessibility, and legal constraints.
4. Choose the project archetype (template) and applicable standards.
5. Record findings to memory (`project`, `client`, `branding`).

## Outputs

- A populated set of memory files.
- A clear problem statement ready for the planning workflow.
