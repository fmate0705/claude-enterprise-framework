# Planning Workflow

**Purpose:** Define how CEF turns discovery findings into an architecture and an actionable build plan before implementation begins.

**Description:** Planning converts understanding into a blueprint. This workflow will govern how Claude selects architecture, chooses a template, defines the information architecture and page/route map, breaks the work into sequenced tasks, and identifies which standards govern which parts of the build. It ends with a plan concrete enough to implement without re-deciding fundamentals mid-flight. CEF plans deliberately so implementation can move fast.

## Inputs

- Discovery outputs and populated memory.
- The chosen archetype and applicable standards.

## Steps (to be authored)

1. Define architecture per the architecture standard.
2. Establish the design system foundation (tokens, components).
3. Map information architecture: pages, routes, and content.
4. Sequence the work into tasks with clear acceptance criteria.
5. Record architecture and key decisions to memory.

## Outputs

- An architecture and design-system foundation.
- A sequenced, acceptance-criteria-driven task plan.
- Updated `architecture` and `decisions` memory.
